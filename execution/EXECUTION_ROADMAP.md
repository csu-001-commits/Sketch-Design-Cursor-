## 1. التسلسل | Sequence

واحد وعشرون أمرًا على ثماني مراحل. **لا يبدأ أمر قبل اكتمال بوابة خروج سابقه.**

| المرحلة              | الأوامر         | بوابة الخروج                                      |
| -------------------- | --------------- | ------------------------------------------------- |
| 0 — Greenfield       | `P00`           | سجل مصادر، سجل قرارات، جرد بيئة، تقرير فجوات      |
| 1 — Foundation       | `P01` → `P04`   | اختبارات تكامل من الطرف إلى الطرف + بروفة استرجاع |
| 2 — Model Gateway    | `P05` → `P09`   | حقن أعطال، قياس جودة، اختبار حمل                  |
| 3 — Golden workflow  | `P10` → `P11`   | مخرَج حقيقي باقتباسات وأثر قابل لإعادة الإنتاج    |
| 4 — Frontend         | `P12` → `P13`   | انحدار بصري، إمكانية وصول، اختبارات صلاحيات       |
| 5 — Sketch Scan      | `P14` → `P15`   | مصفوفة أجهزة، خصوصية، تحقق قياس                   |
| 6 — Launch readiness | `P16` → `P20`   | كل البوابات الحرجة بأدلة ومعتمدة                  |
| 7 — B2B pilots       | خارج هذه الحزمة | عزل، استحقاق، فوترة                               |

## 2. سلسلة الاعتماديات | Dependency chain

```
P00 → P01 → P02 → P03 → P04 → P05 → P06 → P07 → P08 → P09 → P10 → P11
                                                                   ↓
                              P20 ← P19 ← P18 ← P17 ← P16 ← P15 ← P14 ← P13 ← P12
```

سلسلة خطية مقصودة. التوازي ممكن داخل الأمر الواحد، لا بين أمرين، لأن كل أمر يفترض اكتمال بوابة سابقه
— وافتراض غير محقَّق هو مصدر العمل المُعاد.

## 3. لماذا هذا الترتيب | Why this order

**الأساسات قبل الذكاء.** بوابة النماذج بلا تدقيق ولا عزل ولا ميزانيات ليست بوابة إنتاجية بل عميل HTTP.

**البوابة قبل الوكلاء.** الوكيل الذي يستدعي مزوّدًا مباشرةً يتجاوز التوجيه والميزانية والتحقق — ومرة واحدة
تكفي ليصبح النمط دائمًا.

**المحركات الحتمية قبل المسار الذهبي.** المسار يُنتج أرقامًا، والأرقام تحتاج محركًا حتميًا قبل أن تُسلَّم.

**المسار الذهبي مبكرًا.** `P10` قبل الواجهة والمسح والإدارة. المرجع يعطيه الأولوية لأنه **ما يثبت أن
الطبقات تعمل معًا لا منفردة**. تأجيله إلى ما بعد الواجهة يعني اكتشاف خلل التكامل بعد بناء الواجهة فوقه.

**الواجهة بعد استقرار العقود.** بناؤها فوق عقود متحركة يعني بناءها مرتين.

**التدقيق أخيرًا ومستقلًا.** `P20` يستهلك أدلة كل ما سبقه، ويجريه طرف غير المُنفِّذ.

| `OD-V2-02` مخزن البيانات الأساسي     | `P01`               | أمان مستوى الصف يختلف جوهريًا بين الخيارات |

`P00` يصلح لأن يبدأ الآن: فهو ما يحسم بعض هذه القرارات بجمع الحقائق.

## 5. ما هو خارج هذه الحزمة | Out of scope

- **التجارة.** الاشتراكات والاستحقاقات والفوترة متعددة المستأجرين والبوابة البيضاء وسوق الخدمة الذاتية
  — مؤجَّلة بقرار معتمد (`ADR-V2-009`). عقودها محفوظة، وبناؤها ليس الآن.
- **المرحلة السابعة.** برامج B2B التجريبية تبدأ بعد اجتياز بوابات الإطلاق.
- **التوزيع في متجر التطبيقات.** يتطلب قرار إصدار مُصرَّحًا به منفصلًا.

## 6. العلاقة بـ EXECUTION_BLUEPRINT | Relationship to the first blueprint

`EXECUTION_BLUEPRINT/` هي المرجع الأول، المشتق من مصنف v11 بتسعة وستين أمرًا على سبع عشرة مرحلة،
وتغطي المجال الهندسي بعمق أكبر (التسعير، التقييم، التوسع التخصصي، التجارة المؤجلة).

هذه الحزمة هي **المرجع الثاني**: أقل عددًا، وأعلى تفصيلًا تنفيذيًا لكل أمر (اثنا عشر عنصرًا شاملة
التراجع والأدلة)، ومبنية على **المرجع الشامل 2026** الذي يضيف قرار البناء الجديد وتقاعد المكدس القديم.

**الاثنان يتعايشان ولا يلغي أحدهما الآخر.** المرجع الشامل نفسه يُدرج
`Execution Blueprint GREENFIELD.tar.gz` ضمن سجل مصادره. وعند التعارض في اصطلاح — الحالات، أسماء الأوامر،
بنية الأمر — **تحكم هذه الحزمة للتنفيذ الإنتاجي**، ويبقى المرجع الأول مصدرًا للمتطلبات وجردها.
التعارضات مسمّاة في `REQUIREMENTS_TRACEABILITY.md`.
