# ADMIN_CONTROL_PLANE — Sketch Design

مواصفة لوحة التحكم الإدارية ومستوى التحكم. الحالة: `DESIGNED`.

---

## 1. المبدأ الحاكم | Governing principle

لوحة الإدارة **واجهة مفحوصة بالسياسة فوق `Control Plane API`**، وليست واجهة قاعدة بيانات ذات امتياز.
لا سطح استعلام مباشر على قاعدة البيانات في المنتج، بأي شكل، لأي دور.

## 2. الأدوار السبعة المنفصلة | Seven separated roles

| الدور                  | مجاله                         | ما لا يملكه                    |
| ---------------------- | ----------------------------- | ------------------------------ |
| `founder`              | الإشراف العام والاعتماد       | لا يتجاوز قاعدة الشخصين        |
| `platform_admin`       | التشغيل والإعدادات والإصدارات | لا يقرر في المراجعة الهندسية   |
| `security`             | الحوادث، التدقيق، كسر الزجاج  | لا يصادق على مخرج هندسي        |
| `support`              | التشخيص والمساعدة بنطاق محدود | لا يعتمد إعدادًا ولا يرى سرًّا |
| `engineering_reviewer` | القرار المهني على الأدلة      | لا يغيّر إعداد منصة            |
| `finance`              | الفوترة والميزانيات           | لا يصل إلى محتوى المشاريع      |
| `auditor`              | قراءة فقط للتدقيق             | لا يكتب شيئًا                  |

الفصل مقصود. دمج دورين «للتبسيط» يُلغي قاعدة الشخصين عمليًا.

## 3. مصفوفة الصلاحيات | Capability matrix

تُشتَق منها الواجهة ويُفرض بها الخادم — **تعريف واحد**، فلا ينشأ انحراف.

| القدرة                                  | ADMIN  | SUPPORT                  | REVIEWER      |
| --------------------------------------- | ------ | ------------------------ | ------------- |
| إدارة إصدارات الوكلاء وإطلاقها          | اعتماد | قراءة                    | قراءة         |
| إعداد المزوّدين والمسارات               | اعتماد | تشخيص                    | لا شيء        |
| إنشاء واختبار الموصلات ومفاتيح الواجهات | اعتماد | اختبار محدود النطاق      | لا شيء        |
| فحص آثار المشاريع والمهام               | بنطاق  | بنطاق                    | المُسنَد إليه |
| إيقاف أو إعادة محاولة تنفيذ فاشل        | اعتماد | إعادة محاولة آمنة محدودة | لا شيء        |
| مراجعة الأدلة الهندسية                  | قراءة  | لا شيء                   | قرار          |
| ضوابط الفوترة والميزانية                | اعتماد | قراءة الحالة             | لا شيء        |
| حوادث الأمن وتصدير التدقيق              | اعتماد | تصعيد                    | لا شيء        |

**اختبار مُولَّد** يمر على كل خلية من خلايا هذه المصفوفة: المسموح ينجح، وغير المسموح يُرفض.
المصفوفة تُقرأ من التعريف نفسه الذي يفرضه التطبيق.

## 4. الإجراءات الحساسة | Destructive and financial actions

كل إجراء يعلن **قدرته المطلوبة** و**فئة مخاطره**. إجراء بلا الاثنين يفشل في التسجيل.

**قاعدة الشخصين بنيوية لا إجرائية:** سجل الاعتماد مفتاح خارجي **يتطلبه مسار التنفيذ**، لا فحص يجريه.
والطالب لا يكون المعتمد.

**إعادة المحاولة محدودة بالتعريف:** مهمة لا تعلن أنها عديمة التأثر بالتكرار تُرجع `RETRY_NOT_PERMITTED`.
الدعم يملك إعادة محاولة آمنة محدودة فقط.

## 5. الموصلات والأسرار | Connectors and secrets

دورة حياة الموصل: اقتراح ← تحديد نطاق ← اختبار في بيئة معزولة ← اعتماد أمني ← خزنة الأسرار ← نشر ←
مراقبة صحة ← تدوير أو إلغاء.

**لا حقل في أي استجابة قادر على حمل قيمة سرّ.** يُفرض هذا بمخطط الاستجابة ويُختبَر، فلا يتسرب سرّ
حتى بخطأ برمجي. الموصلات تخزّن **مراجع** أسرار فقط.

## 6. كسر الزجاج والخصوصية | Break-glass and support privacy

- كسر الزجاج: باعتماد، محدود بزمن، محدود بنطاق، يُلغى تلقائيًا، ويُنبَّه دور الأمن عند المنح وعند الاستخدام.
- عروض الدعم تُقنّع البيانات الشخصية **افتراضيًا**. إزالة التقنيع تتطلب سببًا مُسجَّلًا وصلاحية منتهية بزمن.
- لا تظهر أسرار مزوّدين خام في الواجهة إطلاقًا.
- الأدوار الإدارية تتطلب إعادة مصادقة قبل الإجراءات المدمّرة.

## 7. دفاتر التشغيل | Operational playbooks

| الدفتر          | التسلسل                                                                                 |
| --------------- | --------------------------------------------------------------------------------------- |
| حادث            | كشف ← تصنيف الشدة ← تخفيف المسار أو القائمة ← حفظ الآثار ← تواصل مع العميل ← تحليل لاحق |
| صيانة           | إعداد مرحلي ← نسخ احتياطي ← نافذة صيانة ← بروفة ترحيل ← اختبارات دخان ← تراجع           |
| دورة التكامل    | اقتراح ← نطاق ← اختبار معزول ← اعتماد أمني ← خزنة ← نشر ← مراقبة ← تدوير أو إلغاء       |
| خصوصية الدعم    | تقنيع ← اعتماد كسر الزجاج ← صلاحية منتهية ← لا أسرار خام في الواجهة                     |
| هندسة الموثوقية | بروفة استرجاع ← أهداف تعافٍ ← اختبار حمل التوسع ← توقّع السعة                           |

كل تنبيه في `ops/alerts/` يشير إلى دفتر موجود، ويفشل فحص الإعداد عند تنبيه بلا دفتر.
والدفتر الذي لم يُجرَّب مسوّدة، لا دفتر.
